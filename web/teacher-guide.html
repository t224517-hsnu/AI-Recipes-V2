餐飲科二年級　2–3 人一組　120 分鐘　教師操作版

糕點辨識與食譜查詢體驗課教案

學生以蛋塔、瑪德蓮、布朗尼為例，完成「蒐集照片、訓練模型、建立食譜、手機測試」四項任務。網站先使用教師提供的模型，再換上各組模型；食譜用 Google 試算表維護，修改後按網站的「重新讀取食譜」。本課為 AI 操作體驗，120 分鐘不包含實際烘焙。

一　學習目標與準備

  1. 能說出模型負責辨識、試算表負責提供食譜，並完成三類測試。
  2. 能以三欄格式新增或修改一筆食譜，並在網站確認發布內容。
  3. 能解釋新增糕點要同時修改模型與食譜，完成進階練習或列出正確步驟。

教師：準備投影機、電腦、穩定網路、可公開的食譜表、三種實物或授權圖片。每組建議一部電腦供訓練、一部手機或平板供辨識；只有行動裝置時，可先用教師模型完成主要流程，訓練由教師投影示範。Teachable Machine 編輯專案與訓練建議先在課堂電腦測通。

分工：拍攝員蒐集照片；模型員訓練與測試；資料員編修食譜與記錄。兩人組由模型員兼任資料員。每類準備 30–50 張訓練照及另外 5 張測試照；此數量為課堂起點，不保證辨識成效。

二　120 分鐘教學流程

時間教師活動學生任務與檢核
0–10 分展示手機辨識與布朗尼糖量修改示範。觀察照片、類別、食譜之間的關係。提問「改食譜需要重訓嗎？」
10–20 分說明流程與三類名稱，示範分工、操作及資料保護。2–3 人分組，確認設備與網路能開啟教師網站。
20–40 分示範多角度、不同背景與光線的照片。每類 30–50 張；另留每類 5 張未見照片，不加入訓練。
40–60 分帶做影像專案、三類訓練、匯出模型。測試保留照片，記下錯誤案例；取得上傳模型網址。
60–75 分帶做三欄食譜表與發布 CSV。複製或匯入範本，確認名稱與模型一致；材料、步驟格內換行。
75–95 分帶做貼連結、儲存、手機辨識及更新示範。三種各測一張；改布朗尼砂糖 50g→40g，重新讀取並核對。
95–110 分示範新增「司康」類別與同名食譜。能力足夠組新增類別重訓；其餘組填寫新增步驟並觀察教師示範。
110–120 分每組 30 秒分享，離堂提問。繳交網站設定連結、測試紀錄與一次成功更新的前後結果。
目前課堂已連接的食譜

開啟課堂食譜檔案。此檔目前為 Google Drive 裡的 Excel，網站已設為預設來源，可直接讀取，不需另外發布 CSV。修改後等 Google 儲存完成，再按網站「重新讀取食譜」。更換其他檔案時可貼編輯連結（須開放連結讀取），或依下方步驟使用已發布 CSV。

教師後台更新方式

從網站進入「教師後台」，輸入教師提供的管理密碼。填入模型及食譜連結，先按「檢查連結與資料」，通過且確認食譜預覽後，再按「上傳並套用」。全班重新整理或重新讀取食譜即可使用新設定。版本紀錄可還原先前的連結與食譜快照，Google 原檔不會被改寫。辨識信心值低於 80% 會提示可能是尚未收錄的新糕點，也應換角度重拍確認。

三　學生只要完成六個步驟

1 建立糕點模型

開啟 Teachable Machine → 開始使用 → 影像專案 → 標準影像模型。三類分別命名「蛋塔」「瑪德蓮」「布朗尼」。每次拍一種糕點，避免拍到人臉，讓同一類包含不同盤子、背景與角度；三類數量盡量接近。

2 訓練 測試 匯出

按訓練模型，完成後用未參與訓練的照片測試。記錄每類 5 張的實際正確張數，不將單張信心值當準確率。匯出模型 → TensorFlow.js → 上傳模型 → 複製模型網址。保留編輯專案或下載專案檔，日後新增類別需要它；僅有已匯出的模型網址無法還原所有訓練照片。

教師備用模型：https://teachablemachine.withgoogle.com/models/il-xR9WBN/。已核對 metadata 的三個類別名稱；真正食物辨識成效需由教師以課堂照片測試。

一種糕點一列；材料與步驟各放一格，一行一項。電腦版通常可在編輯儲存格時用 Windows Ctrl+Enter 或 Mac ⌘+Enter 換行；行動版可在儲存格編輯模式使用鍵盤換行鍵，依裝置操作為準。新增整列即可新增食譜，刪除整列即可刪除食譜。不要合併儲存格或輸入重複名稱。這些為教學示例，模具容量與烤箱會影響產量、溫度與時間，實作烘焙前由餐飲教師確認。

4 發布 CSV 並貼入網站

試算表選「檔案 → 共用 → 發布到網路」，指定「食譜」工作表，格式選「逗號分隔值 CSV」，按發布並複製連結。確認已發布設定勾選「內容變更時自動重新發布」（若介面有此選項）。也可直接使用已開放連結讀取的 Google 試算表或 Excel 編輯連結，由教師在後台檢查並套用。

連結通常為 https://docs.google.com/spreadsheets/d/e/…/pub?gid=…&single=true&output=csv。只發布食譜，不放學生姓名、成績或私人資料。學校管理員若禁止發布，可保留目前課堂設定，待教師確認讀取權限後再更新。

5 手機辨識與食譜更新

教師先在後台完成設定，學生開網站 → 允許相機或選拍照／上傳 → 按辨識。相機將使用畫面中央正方形區域。信心值低於 80% 會請學生重拍，不自動推薦食譜。80% 是本課操作門檻，並非可靠度保證。

教師的更新示範劇本
  1. 網站手動選「布朗尼」，先確認材料為砂糖 50g，且資料來源顯示 Google 試算表。
  2. 回食譜表 B4，把「砂糖 50g」改成「砂糖 40g」，其餘行保持不變。
  3. 回網站按「重新讀取食譜」，確認顯示 40g；這個改動是資料更新示範，實際配方由教師確認。
  4. Google 可能需要數分鐘發布，請在前段課程先改好，稍後再次讀取。刷新時間代表抓取時間，不保證 Google 已發布最新修改。
  5. 課程結束可將 40g 還原 50g，再次重新讀取。學生裝置各自按更新，不會自動被教師的按鈕刷新。

6 自行新增司康或其他糕點

回原始 Teachable Machine 編輯專案 → 新增「司康」類別 → 蒐集照片與保留測試照 → 重新訓練四類 → 重新上傳 → 試算表新增一列，辨識名稱同樣填「司康」，填材料與步驟 → 教師後台填入新模型與食譜連結 → 檢查並上傳套用 → 學生重新讀取。若只是加食譜而未重訓，模型不會多認識一種食物；若只有模型而無同名食譜，網站會提示找不到食譜。可用相同方法自行增加其他糕點。

四　網站入口與部署

本版包含教師後台、共用設定與版本紀錄，可透過套件中的 GitHub Actions 部署到 Cloudflare Workers。老師可在 Google Sites（Google 協作平台）加入「開始糕點辨識」按鈕，連到此網站，讓學生用新分頁開啟相機。兩個網站的存取權限需各自設定；協作平台的分享不會自動變更辨識網站權限。

若要移至學校主機，需由資訊人員提供後端執行環境、持久儲存與安全的管理密碼設定。此版的後台不能只靠 GitHub Pages 等靜態檔案空間運作。手機使用 HTTPS 網址與現代瀏覽器；相機無法開啟時可改用拍照／上傳。模型與食譜更新需要網路。

六　常見問題與課前驗收

  • 辨識總是同一類：檢查是否學到盤子或背景；讓每類都換背景、增加不同角度，重新訓練。單張只能放一種糕點。
  • 找不到食譜：核對模型類別與 A 欄名稱完全相同，例如「蛋塔」與「蛋撻」不會自動視為同名。
  • Google 讀不到：確認 CSV 發布網址、選對工作表、標題三欄正確，且學校允許發布。失敗時畫面會標明仍顯示示例或舊資料。
  • 讀到了卻未更新：Google 發布有延遲，確認自動重新發布，等候後重讀；網站不會修改 Google 表。
  • 手機無法開相機：確認 HTTPS 與瀏覽器權限，改用系統相機拍照後上傳。

課前依序驗收：□ 教師與另一部手機都能開啟正式網站　□ 模型載入　□ 三種糕點各測一張　□ CSV 顯示三種食譜　□ 糖量改動能讀回　□ 新增一列能出現　□ 刪除該測試列後網站同步移除　□ 模型有類別而食譜不存在時有明確提示。三類模型無法可靠拒絕所有未知物件；課程延伸可新增「其他／非糕點」類別改善，但仍須測試。
